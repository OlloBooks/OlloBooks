## How to emit a metric — `.` (web)

**This app's FireWeave files:** control points `src/fireweave/control-points.ts`; start `src/fireweave/start.ts`, imported first by `src/main.tsx`; build config `vite.config.ts`; stamps `.fireweave/stamps.ts`.

**Client:** `posthog`

**Import, as it appears in this repo:** `import posthog, { isPostHogConfigured } from '../posthog.ts'`

**Counter:** `posthog.capture(event, attributes) — e.g. posthog.capture('sudoku_maker_opened'); captureBookEvent(event, options) guards with isPostHogConfigured and attaches bookAttributes(options)`

**Histogram / timing:** Not recorded at setup: read the examples below.

**Where the instrument comes from:** src/posthog.ts: posthog-js client initialized from VITE_POSTHOG_KEY/VITE_POSTHOG_HOST (import.meta.env), guarded everywhere by isPostHogConfigured; also exports posthogLog.info/error which call posthog.logger.info/error (structured logs, not metrics)

**Wrapper to prefer over the raw client:** captureBookEvent(event, options) in src/ui/SudokuMaker.tsx — checks isPostHogConfigured, then posthog.capture(event, bookAttributes(options))

**Tag / label convention (including the cohort key):** event properties object built by bookAttributes(options): difficulty, grid_size, puzzle_count, puzzles_per_sheet, includes_answer_key

**Real examples from this repo:**

- `src/ui/Library.tsx:7`

  ```
  if (isPostHogConfigured) posthog.capture('sudoku_maker_opened')
  ```
- `src/ui/SudokuMaker.tsx:67`

  ```
  posthog.capture(event, bookAttributes(options))
  ```
- `src/ui/SudokuMaker.tsx:107`

  ```
  captureBookEvent('sudoku_book_generated', snapshot)
  ```

### What this surface already emits
